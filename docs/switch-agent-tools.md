# Switch on this Windows PC

Run RevenueOps at http://127.0.0.1:5173 (use `./start.ps1`). Open the dashboard once and wait for “Shared workspace connected” before asking the agent to work. Existing browser data is merged on that first connection. The original is preserved in browser key `css-revenueops.pre-shared-backup` and in `data/migration-backups`. Conflicting IDs are copied with new IDs rather than overwritten. Use the same browser origin as before: 127.0.0.1:5173.

The shared store is `data/workspace.json`. Do not edit this file manually. Writes go through validated, atomic server operations. The dashboard polls every 1.2 seconds. Concurrent changes to the same record are rejected instead of silently overwritten. If a conflict occurs, export local work, reload, and reconcile from the backup. Browser backup/restore remains available.

Register the Switch Codex agent with working directory `C:\Users\coled\Projects\RevenueOps`. The agent must actually run on this Windows PC, not inside a managed container. Keep bypass permissions off. Never commit or share `data/agent-token`; the CLI reads it automatically. The API binds to loopback and rejects requests without a local agent token or same-origin browser headers. No outbound mail endpoints exist.

## Agent instructions

Use `node scripts/agent.mjs TOOL arguments.json` from the project directory. Write arguments as a JSON file; do not embed untrusted prospect text in shell commands. Read the command result and report IDs only after success. A nonzero exit means the action failed. Use list_prospects before create_prospect to avoid duplicates. Use the returned IDs for corrections. Never edit application code, server data files, or credentials during sales operations. Never send outreach.

| Tool | JSON arguments |
|---|---|
| list_prospects | `{"query":"Alder"}` |
| get_state | `{}` |
| create_prospect | `{"company":"Alder Demo Consulting","contact":"Mara Ellis","problem":"Five hours per week copying inquiries","stage":"Discovery"}` |
| update_prospect | `{"id":"PROSPECT_ID","changes":{"problem":"Two hours per week copying inquiries"}}` |
| log_activity | `{"prospectId":"PROSPECT_ID","kind":"Note","text":"Corrected estimate to two hours."}` |
| save_draft | `{"prospectId":"PROSPECT_ID","subject":"Workflow question","body":"Your draft text"}` |
| save_draft (update) | `{"id":"DRAFT_ID","prospectId":"PROSPECT_ID","subject":"Revised question","body":"Revised draft text"}` |

Omit subject/body to generate a local template for a new draft. All agent draft saves set status to Draft; review remains a human step. get_state includes drafts so the agent can locate an existing one. No Switch-specific CLI or API commands are invented here: Switch invokes the existing Codex agent, which runs these project tools.

## Operation

Both `npm run dev` and `npm run preview` include the local API. A static-only deployment of `dist` does not. Back up the data directory while the server is stopped, or export JSON from Settings while running. The local token is shared by trusted local agents; this is not a multi-user or publicly exposed service. Keep data and tokens out of source control.
